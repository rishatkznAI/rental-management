## Найденные дефекты

### P1 — дата без времени отображается на день раньше

В путевом листе и ручной финансовой операции введена дата `02.08.2026`, но после сохранения таблицы показывают `01.08.2026`. Дефект воспроизвёлся в двух независимых разделах.

Вероятная общая причина: `formatDate()` разбирает строку `YYYY-MM-DD` через `new Date(date)`, то есть как UTC-полночь; в часовом поясе браузера западнее UTC дата становится предыдущим календарным днём. Для date-only значений нужен разбор без временной зоны.

Риск: неверные даты финансовых операций, путевых листов и других документов у пользователей в части часовых поясов.

### P2 — legacy-доставка не сохраняется без нового обязательного контакта

У старой записи `DEMO-DELIVERY-001` не было контактного лица. После изменения только комментария кнопка сохранения вернула `Поле «Контактное лицо» обязательно`. Сохранение стало возможным только после ручного заполнения контакта и телефона.

Риск: существующие долгоживущие JSON-записи нельзя отредактировать, пока пользователь не восстановит новое обязательное поле.

### P2 — KPI утилизации на дашборде не открывает расшифровку

Кнопка `Утилизация парка 65% · В аренде 13/20` нажата повторно с ожиданием. Диалог и иной видимый результат не появились. Кнопка `Расшифровка` рядом работает корректно.

### P2 — «Добавить оплату» в списке аренд завершается без результата

При отсутствии выбранной аренды кнопка активна, но после клика нет перехода, диалога, подсказки или ошибки. Нужна либо блокировка с объяснением, либо форма выбора аренды.

### P2 — неоднозначные вторичные действия документов

- `Настройки полей` из раздела документов оставляет пользователя на экране контроля без видимого изменения.
- `Создать спецификацию` из карточки только что созданного договора закрывает карточку и возвращает в реестр, не открывая мастер и не показывая сообщение.

### P1 — гарантийный механик не может обновить разрешённые поля заявки

Изолированный повторный E2E-сценарий `warranty-mechanic-ui-smoke` стабильно получает неуспешный ответ при PATCH разрешённых критических полей сервисной заявки. Это не зависит от demo-seed и повторилось на пустой базе.

Риск: гарантийный механик видит рабочий контур, но не может завершить предусмотренное ролевое действие. Требуется проверить backend access control для подроли гарантийного механика и перечень разрешённых полей.

### P2 — сервисные фото дают 404 вместо корректного placeholder

Два изолированных E2E-сценария подтвердили проблему:

- защищённое фото не появляется в карточке заявки с ожидаемым `alt`;
- отсутствующий архивный файл запрашивается по `/uploads/external-photos/...`, отвечает `404` и пишет ошибку в console вместо бесшумного fallback/placeholder.

### P3 — платёжная форма не имеет dialog-семантики

Форма `Новый платёж` визуально открывается и сохраняет данные, но не представлена как `[role="dialog"]`. Это ломает accessibility-контракт и два E2E-теста, ожидающих модальное окно.

### P3 — demo-набор не позволяет завершить новую аренду

В форме новой аренды выбранный demo-клиент не имеет доступных объектов и договоров, поэтому `Создать аренду` остаётся недоступной. Это ограничение тестового набора, а не подтверждённый production-дефект.

## Ожидаемые предупреждения и ограничения

- Отправка в MAX вернула ожидаемое предупреждение: для demo-перевозчика не привязан пользователь MAX.
- GPRS gateway отключён, поэтому реальные пакеты и команды не отправлялись.
- Подтверждение отмены доставки использует нативный `confirm`; финальный ответ в in-app Browser автоматизировать не удалось. Сам вызов подтверждения проверен.
- Нативные окна печати, выбора файла и сохранения скачанного файла не подтверждались на уровне ОС; проверено, что соответствующие кнопки запускают действие.
- Разрушительные удаления production-сущностей не выполнялись. Все допустимые статусные переходы и закрытие зарплатного периода выполнялись только в изолированной базе.

### Классификация E2E-падений

Полный E2E-набор смешивает локальные, staging и production smoke-gates, поэтому его итоговый exit code ожидаемо ненулевой без внешних секретов и URL.

1. **10 environment-gated сценариев** требуют `PRODUCTION_*` или `STAGING_*` и не могут выполняться в локальном demo-контуре.
2. **Устаревшие UI-контракты**: отдельная кнопка `Выйти` вместо menuitem в аватаре; маршрут `/crm` вместо редиректа в `Продажи`; старые admin-tabs; `Добавить договор` вместо `Создать договор`; ожидание modal/dialog там, где теперь используется sheet; нестрогие локаторы, находящие два одинаковых текста.
3. **Изоляция данных**: часть role-smoke тестов создаёт повторную строку `gantt_rentals` и получает `DUPLICATE_GANTT_RENTAL_LINK`; demo-набор также не обеспечивает прекондейшен новой аренды.
4. **Подтверждённые продуктовые кандидаты**, повторившиеся на пустой базе: 404 сервисных фото и отказ PATCH для гарантийного механика.

При этом основной локальный smoke-набор внутри полного прогона прошёл: авторизация, создание клиента/техники/аренды/сервисной заявки, ограничения ролей, sidebar, адаптивный дашборд, карточки, пагинация bounded-loading и подтверждения административных действий.
