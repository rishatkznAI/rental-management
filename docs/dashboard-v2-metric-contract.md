# Dashboard V2: контракт управленческих метрик

Документ фиксирует семантику Executive Cockpit. Dashboard только читает канонические коллекции и не сохраняет производные значения.

## Выручка месяца

- **Metric:** начисленная арендная выручка с начала текущего месяца по текущую дату.
- **Source:** `gantt_rentals` через существующую выборку планировщика и `calculateRentalBilling`.
- **Formula:** сумма `finalRentalAmount` договоров, пересекающих период, после `shouldCountRental`; период расчёта — от первого дня месяца до текущей даты, с учётом downtime.
- **Scope:** только учитываемые арендные договоры; отменённые и исключённые существующими правилами записи не входят.
- **Date:** календарный месяц в локальной бизнес-дате Dashboard. Сравнение — тот же номер дня прошлого месяца.
- **Null:** ошибка/загрузка источника показывается как недоступность; подтверждённое отсутствие начислений показывается как пустое состояние, не как неизвестный ноль.
- **Permissions:** только при праве просмотра аренд.
- **Drill-down:** `/rentals`.
- **Forecast:** детерминированные начисления уже известных договоров до конца месяца. Новые сделки не предполагаются. План показывается только при полном покрытии активного парка `plannedMonthlyRevenue`.

## Загрузка парка

- **Metric:** доля активного арендного парка, занятого активной арендой.
- **Source:** `equipment` и канонические аренды планировщика.
- **Formula:** уникальные единицы техники в действующей аренде / активный арендный парк × 100%.
- **Scope:** знаменатель формируется существующим `activeRentalFleetLookup`; сервис, резерв и неактивность не переопределяют договорные связи телеметрией.
- **Date:** текущий срез; изменение — в процентных пунктах к срезу ровно 30 дней назад при том же знаменателе.
- **Null:** при отсутствии активного парка показывается `—` и причина; это не 0%.
- **Permissions:** только при праве просмотра техники.
- **Drill-down:** `/equipment?status=rented`.

## Просроченная дебиторка

- **Metric:** подтверждённый непогашенный остаток с наступившим сроком оплаты.
- **Source:** `payments`, `payment_allocations`, `gantt_rentals` и канонический debt-aging helper.
- **Formula:** сумма непогашенных остатков строк aging, признанных просроченными существующими финансовыми правилами.
- **Scope:** группировка и ссылки строятся по `counterpartyId`/`clientId`; имя клиента используется только как подпись. Допустимы только канонические или однозначно восстановленные статусы идентичности.
- **Date:** на текущую дату; возраст — максимальное подтверждённое число дней просрочки.
- **Null:** если хотя бы один обязательный источник не подтверждён, показывается `—`/недостаточно данных. `0 ₽` допустим только при успешно загруженных источниках и подтверждённом отсутствии просрочки.
- **Permissions:** при праве просмотра финансов или платежей; детали клиента доступны только при праве просмотра клиентов.
- **Drill-down:** `/finance?tab=receivables` при доступе к Finance, иначе `/payments`; должник — `/clients/:clientId` только при соответствующем праве либо receivables по `counterpartyId`.

## Поступления месяца

- **Metric:** фактически полученные платежи текущего месяца.
- **Source:** `payments`.
- **Formula:** сумма положительного фактического оплаченного значения только по записям с `paidDate` внутри месяца.
- **Scope:** ожидаемые платежи, `dueDate`, начисления, исходящие операции и внутренние переводы не считаются поступлениями.
- **Date:** дата фактической оплаты `paidDate`.
- **Null:** ошибка/загрузка источника даёт `—`. Если существуют положительные платежи без `paidDate`, покрытие считается частичным и известная сумма маркируется `≥`; ноль не утверждается.
- **Permissions:** при праве просмотра финансов или платежей.
- **Drill-down:** `/payments`.

## Денежные оценки рисков

Сумма показывается только при доказуемом источнике: каноническая непогашенная дебиторка или положительный `estimatedLoss` управленческой очереди. Просроченный возврат, окончание аренды, простой и сервисная заявка остаются количественным риском без денежной оценки, пока нет подтверждённой договорной стоимости точного пересечения периодов.

## Ограничения данных

- Нет отдельного утверждённого финансового плана — Dashboard не синтезирует его из факта.
- Нет надёжного пользовательского snapshot `lastSeen` — блок «с последнего визита» не показывается.
- Нет исторических snapshot’ов uptime/AR — направление и прогноз строятся только там, где доступен сопоставимый первичный ряд.
- Sales появляется только при включённом CRM и праве `view crm`; взвешенный прогноз равен `budget × probability`, а неполное покрытие вероятностями маркируется явно.
